## 1. How to find time complexity

1. Identify the input size `n`.
2. Count how many times the main operation runs.
3. Keep the fastest-growing term and drop constants: `3n² + 5n + 2` becomes O(n²).
4. Sequential blocks add. Nested blocks multiply.

| Code pattern | Complexity |
|---|---|
| Single loop to `n` | O(n) |
| Loop inside a loop, both to `n` | O(n²) |
| Loop that halves the range each time (`i /= 2`) | O(log n) |
| Loop to `n` with a halving loop inside | O(n log n) |
| Two separate loops one after another | O(n) + O(n) = O(n) |

### Worked examples

```java
// Example A: O(n)
for (int i = 0; i < n; i++) total += a[i];

// Example B: O(n^2)
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] + a[j] == target) found = true;

// Example C: O(log n)
for (int i = n; i > 0; i /= 2) steps++;
```

## 2. Space complexity

Space complexity measures the **extra** memory used.

| Algorithm | Extra space | Reason |
|---|---|---|
| Iterative sum | O(1) | One variable |
| Merge sort | O(n) | Temporary arrays |
| Recursive DFS | O(h) | Call stack as deep as the graph path |
| BFS | O(V) | Queue and visited set |

---

## 3. Analysing recursion

Recursive running time is written as a recurrence.

| Algorithm | Recurrence | Result |
|---|---|---|
| Binary search | T(n) = T(n/2) + O(1) | O(log n) |
| Merge sort | T(n) = 2T(n/2) + O(n) | O(n log n) |
| Naive Fibonacci | T(n) = T(n−1) + T(n−2) | O(2ⁿ) |
| Factorial | T(n) = T(n−1) + O(1) | O(n) |

**Merge sort reasoning:** the array is halved log n times, and each level does O(n) work merging, so the total is n × log n.

**Amortised cost:** appending to a dynamic array occasionally costs O(n) when it resizes, but doubling the capacity makes the average cost per append O(1).

## 4. Tracing an algorithm by hand

Tracing means recording variable values step by step. It is the fastest way to find logic errors.

**Insertion sort on `[5, 2, 4, 1]`**

| Pass | Key | Array after pass | Explanation |
|---|---|---|---|
| Start | – | 5 2 4 1 | |
| 1 | 2 | 2 5 4 1 | 2 moves before 5 |
| 2 | 4 | 2 4 5 1 | 4 moves before 5 |
| 3 | 1 | 1 2 4 5 | 1 moves to the front |

## 5. Trade-offs and choosing a structure

| Need | Good choice | Why | Cost |
|---|---|---|---|
| Fast lookup by key | Hash table | O(1) average | No ordering, extra memory |
| Sorted data and range queries | Balanced BST | O(log n), ordered | More complex |
| Always process the smallest/largest first | Heap | O(log n) insert/remove | No fast search |
| Frequent insert/delete at the ends | Deque / linked list | O(1) | No fast random access |
| Reverse order, undo | Stack | Simple LIFO | Only top accessible |
| Fair processing order | Queue | FIFO | Only front accessible |

**Time vs space:** a hash set can reduce a duplicate check from O(n²) to O(n), but uses O(n) extra memory.

```java
// Brute force: O(n^2) time, O(1) space
boolean hasDuplicate(int[] a) {
    for (int i = 0; i < a.length; i++)
        for (int j = i + 1; j < a.length; j++)
            if (a[i] == a[j]) return true;
    return false;
}

// With a HashSet: O(n) time, O(n) space
boolean hasDuplicateFast(int[] a) {
    java.util.Set<Integer> seen = new java.util.HashSet<>();
    for (int x : a) if (!seen.add(x)) return true;
    return false;
}
```

## 6. Problem-solving checklist

1. Restate the problem and note constraints.
2. Try a small example by hand.
3. Write a brute-force idea and its complexity.
4. Look for a structure that removes repeated work.
5. Code it, then trace one normal case and one edge case (empty input, one element, duplicates).
6. State the final time and space complexity.
