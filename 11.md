## 2. Linux and SQL (Course 4)

```bash
ls -l /var/log                     # list files with permissions
grep "Failed password" auth.log    # find failed SSH logins
grep -c "Failed password" auth.log # count them
chmod 640 report.txt               # owner read/write, group read, others none
```

Linux permissions are shown as `rwx` for owner, group and others. `chmod 640` means owner `rw-` (6), group `r--` (4), others `---` (0). The principle of **least privilege** gives users only the access they need.

```sql
-- Failed logins from a given country in the last day
SELECT username, ip_address, login_time
FROM log_in_attempts
WHERE success = 0 AND country = 'XX'
ORDER BY login_time DESC;

-- Users with the most failed attempts
SELECT username, COUNT(*) AS failures
FROM log_in_attempts
WHERE success = 0
GROUP BY username
ORDER BY failures DESC;
```

## 3. Assets, threats and vulnerabilities (Course 5)

| Term | Meaning | Example |
|---|---|---|
| Asset | Anything of value to protect | Customer database |
| Threat | Possible cause of harm | Phishing campaign |
| Vulnerability | Weakness that can be exploited | Unpatched software |
| Exploit | Using a vulnerability | SQL injection |

- Assets are classified (public, internal, confidential, restricted) so protection matches value.
- **Vulnerability management:** find, assess, prioritise, fix, verify. Public references include CVE entries and the OWASP Top 10 for web applications.
- Defence in depth uses several layers so one failure does not expose everything.

## 4. Detection and response (Course 6)

**Incident response lifecycle:** Preparation → Detection and analysis → Containment, eradication and recovery → Post-incident activity.

| Tool type | Purpose |
|---|---|
| IDS / IPS | Detect (and block) suspicious network activity |
| Packet analyser | Inspect captured traffic to investigate an incident |
| SIEM | Collect and correlate logs, raise alerts |

Evidence handling matters: document what was found, when and by whom, and preserve logs.

## 5. Python for security tasks (Course 7)

```python
# Count failed logins per IP from a log file
from collections import Counter

failures = Counter()
with open("auth.log") as f:
    for line in f:
        if "Failed password" in line:
            ip = line.split()[-4]          # position depends on the log format
            failures[ip] += 1

for ip, count in failures.most_common(5):
    print(ip, count)
```

Automation reduces manual effort and human error when checking large logs.

## 7. Applying the concepts – scenario

**Scenario:** a company's logs show 200 failed logins for one account from an unfamiliar IP in ten minutes, followed by one success.

| Step | Action | Concept used |
|---|---|---|
| 1 | Identify: likely a brute-force or credential-stuffing attack | Threat identification |
| 2 | Confirm using log search (`grep`, SQL query by account and IP) | Linux / SQL |
| 3 | Contain: lock the account, block the IP at the firewall, force a password reset | Containment |
| 4 | Investigate what the account accessed after the successful login | Detection and analysis |
| 5 | Recover and report: restore, notify, document timeline | Recovery, communication |
| 6 | Prevent: enable multi-factor authentication, add account lockout and rate limiting | Controls, defence in depth |
